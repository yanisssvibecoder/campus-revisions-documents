 Le mandat

 L’ATI vous demande de donner forme à cette idée. Pour ce faire vous devez réaliser une
 application qui permettra à une personne étudiante de connaître sa progression après
 chaque évaluation pour chacun de ses cours. L’application devra également permettre de
 suivre la collaboration de chaque équipier.ère dans les travaux d’équipe auxquels cette
 personne participe.

 Les critères pour la correction sont dans le tableau ci-dessous. Vous pouvez opter pour le
 niveau de complexité lié à chaque critère, la valeur présentée est alors la note maximale.
 Donc,  si pour le modèle conceptuel, vous optez pour le niveau intermédiaire, la note
 maximale sera de 16 points si la correction confirme une maîtrise complète de ce niveau.

 Votre livrable principal est une application fonctionnelle construite sur Softr et Airtable, avec
 les récits et le modèle conceptuel en                                    « complément ».

Vos livrables

1.   Récits utilisateurs
Votre équipe devra d’abord aller à la rencontre des personnes qui utiliseraient cet outil :
recueillez des besoins auprès d’au moins deux personnes qui ne font pas partie de votre
équipe, en vous appuyant sur les profils de Yasmine, Zack et Aleks comme point de départ.
Ce que vous découvrirez dépassera peut-être ce que le cas vous dit déjà.

Rédigez les récits utilisateurs qui décrivent ce que votre application doit permettre de faire.
Chaque récit doit suivre la structure vue en cours : en tant que [rôle], je veux [fonctionnalité],
afin de [bénéfice]. Vos récits doivent être ancrés dans les besoins que vous aurez collectés
auprès d’utilisateurs réels.

2.  Modèle conceptuel
Concevez le modèle de données de votre application. Pour vous orienter, l’ATI a identifié
trois entités lors de ses discussions initiales :

                COURS |  ÉVALUATION |  CONTRIBUTION

Votre modèle devra les inclure, les compléter si nécessaire et définir les relations entre elles.
Le modèle que vous implémenterez dans  Airtable  doit  être un modèle  logique
correspondant à votre modèle conceptuel. Ce modèle doit respecter l’intégrité référentielle,
vous n’avez pas à présenter votre modèle logique (uniquement le schéma de votre modèle
conceptuel).


3.  Application Softr + Airtable
Construisez votre application. Elle doit être fonctionnelle : les données doivent pouvoir être
saisies et consultées. Votre base Airtable doit refléter votre modèle conceptuel.



4.  Automatisation
Ajoutez une automatisation à votre application. Choisissez parmi les trois options ci-dessous.
Le nombre de points disponibles varie selon votre choix. Ces options ne peuvent pas être
combinées et le pointage n’est pas cumulatif.

Option A : Rappel de remise (9 points) : envoyer automatiquement un courriel 48 heures
avant la date d’une évaluation.
Option B : Notification de contribution (12 points) : lorsqu’une personne enregistre une
contribution dans l’équipe, notifier les autres membres par courriel.
Option C : Alerte                             (15 points) : lorsque la note requise pour atteindre
l’objectif de fin de session dépasse 100 %, mettre à jour automatiquement un champ de                   « Objectif compromis »
statut dans Airtable.

Le reste vous              appartient !
