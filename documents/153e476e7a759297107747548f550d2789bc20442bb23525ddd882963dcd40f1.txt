BASE DE DONNÉES RELATIONNELLE : PRINCIPAUX CONCEPTS

Les bases de données constituent le cœur des systèmes d’information transactionnels. Les
réponses à des questions telles que « Combien me doit un tel client ? Quand tel ou tel client
a-t-il commandé pour la dernière fois ? Quels sont les produits d’une commande ? Quels sont
les produits d’un fournisseur » se trouvent dans les bases de données de l’organisation. En
plus, lorsqu’on traite une transaction, on saisit et on modifie des données qui sont dans les
bases de données.

Avec l’informatisation des processus d’affaires, les organisations se construisent d’énormes
bases de données détaillant pratiquement tous les aspects de leurs opérations, des entrées et
sorties d’argent en passant par les commandes faites par les clients, les niveaux d’inventaire et
les heures travaillées par les employés. Ces bases de données constituent de véritables
entrepôts qui, lorsqu’elles sont exploitées judicieusement, peuvent fournir aux entreprises un
avantage compétitif important.
Par exemple, McKesson Corp, un distributeur de produits pharmaceutiques, conserve des
données  sur  les commandes  journalières  qu’elle  reçoit de  ses  clients pour  ses285 000 produits répartis dans ses 50 entrepôts, soitREDISTRIBUERplus de 1,4 million de lignes de
commandes différentes par jour. Selon les dernières statistiques, Mastercard gère près de
400 millions de transactions journalières. De son côté, Wal-Mart emmagasine depuis
longtemps  les  données  provenant  des  caisses  enregistreuses  dans  ses quelque10 800 magasins et se sert de cette informationPASpour prédire le volume de chaque produit
qui sera vendu dans chaque magasin.Les entreprises se servent de leurs basesNEde données non seulement pour obtenir des
réponses à des questions bien précises, mais aussi pour découvrir des patterns nouveaux. On
utilise des logiciels spécialisés qui fouillent les bases de données et les analysent dans le but
d’établir des associations entre les variables que l’on ne soupçonnait pas. Par exemple, les
chaînes de supermarchés analysent couramment  les données provenant des caisses
enregistreuses afin de découvrir les profils d’achat des consommateurs. Les résultats des
analyses permettent aux chaînes de revoir la disposition de leurs étalages pour qu’ils
correspondent mieux aux comportements des consommateurs.       TRAVAIL,

3 Enregistrement
Chaque ligne de la table est aussi appelée un enregistrement. Un enregistrement est défini par
l’ensemble des valeurs composant la ligne. Par exemple, l’ensemble des valeurs (P001 ; Écran                   REDISTRIBUER27 po ; 245 ; 285,00) définit l’enregistrement du produit P001.

5 Clé primaire

Le concept de clé est fondamental à la compréhension des bases de données. On dit d’un attribut qu’il
est clé dans une table s’il permet d’identifier de façon unique les enregistrements de celle-ci. Un attribut
clé doit avoir les deux propriétés suivantes : il doit être unique et obligatoire ; cette dernière propriété
est nécessaire pour assurer l’unicité des enregistrements. En effet, si l’attribut n’est pas obligatoire,
plusieurs enregistrements peuvent prendre la valeur nulle. Des exemples d’attribut clé seraient le
Numéro d’employé dans une table EMPLOYÉ, le Numéro de client dans une table CLIENT, le Numéro decommande dans une table COMMANDE.       REDISTRIBUER
Lorsque deux ou plusieurs attributs d’une même table peuvent jouer le rôle de clé, alors on dit que ces
attributs sont des candidats pour devenir clé primaire de la table. Par exemple, une table qui contient les
attributs Numéro d’employé et Numéro d’assurance sociale possède deux candidats pour devenir clé          PASprimaire de la table.

Pour assurer l’unicité des enregistrements, il est parfois nécessaire de combiner plusieurs attributs.Lorsque la clé primaire est composée de plusieursNEattributs, on parle de clé primaire composée ou
concaténée. Les attributs composant la clé primaire doivent nécessairement avoir les deux propriétés
suivantes : chaque attribut membre de la clé primaire doit être obligatoire et les valeurs pour les deux
attributs pris ensemble doivent être uniques. Il est important de remarquer que dans le cas d’une clé
primaire concaténée, chaque attribut pris individuellement n’est pas unique.
