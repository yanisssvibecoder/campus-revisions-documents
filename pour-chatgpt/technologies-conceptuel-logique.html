analogy

Avant de construire une maison, on choisit les pièces et leurs relations ; ensuite, on précise murs et portes. Le modèle conceptuel parle des choses du métier ; le logique prépare leur organisation dans les tables.

explanation

  1. Le modèle conceptuel décrit les entités d’affaires, attributs, relations et règles indépendamment d’une interface précise. Lire une règle dans les deux sens : un Client peut passer 0 à plusieurs Commandes ; une Commande appartient à exactement 1 Client.

  2. Une cardinalité indique le nombre minimal et maximal de liens possibles pour une occurrence. Facultatif ne signifie pas plusieurs ; obligatoire ne signifie pas unique. Chaque borne doit venir d’une règle d’affaires.

  3. Le modèle logique traduit les entités en tables, choisit des clés et place les références. En un-à-plusieurs, référence côté plusieurs. En plusieurs-à-plusieurs, créer une table intermédiaire pour le lien et ses attributs.

  4. Un dictionnaire de données précise nom, sens, type, taille ou format, statut obligatoire, valeurs acceptées et règle de calcul/validation. Par exemple téléphone comme donnée de contact ; ne pas choisir automatiquement un type numérique qui supprime un zéro initial.

  5. Le modèle implémenté doit correspondre aux règles : un champ lié Commande→Client n’autorise qu’un client si la règle dit un. Le retour Client→Commandes permet plusieurs. Les champs calculés/lookup/rollup sont présentés comme virtuels dans la convention du cours.

  6. Dans le travail#1, le modèle conceptuel est remis et la base Airtable représente un modèle logique correspondant ; le schéma logique n’est pas un livrable séparé selon le document, mais il doit être cohérent pour construire l’application.

formulas

    workedExamples

    1. title

      Règle dans deux sens — exemple original

      prompt

      Un livre peut avoir plusieurs auteurs ; un auteur peut écrire plusieurs livres. La contribution indique son rôle.

      steps

      1. Relation plusieurs-à-plusieurs.

      2. TablesLivre etAuteur avec clés.

      3. TableParticipation référenceLivre etAuteur ; rôle y appartient.

      4. Vérifier si un livre sans auteur est possible et choisir les minima d’après le métier.

      answer

      Le rôle est un attribut de la relation, pas automatiquement de l’auteur.

      pitfall

      Placer un unique auteur dans chaqueLivre si plusieurs sont permis.

    2. title

      Dictionnaire de paiement — exemple original

      prompt

      Trois moyens acceptés : comptant, débit, crédit. Comment définir le champ ?

      steps

      1. Sens : moyen choisi pour la transaction.

      2. Type : sélection unique dans un domaine fermé.

      3. Valeurs acceptées : les trois catégories.

      4. Obligatoire si la commande validée nécessite un moyen.

      5. Interface : liste claire ; base et traitement valident la même règle.

      answer

      Une règle précise traduite en contrainte de saisie.

      pitfall

      Laisser du texte libre puis essayer de deviner si «cred», «carte» et «visa» sont équivalents.

    recall

    1. prompt

      Différence conceptuel/logique ?

      answer

      Conceptuel : objets et règles ; logique : tables, clés et liens correspondants.

      hint

      Métier puis structure.

      id

      technologies-conceptuel-logique-r1

    2. prompt

      Pourquoi lire la cardinalité dans deux sens ?

      answer

      Chaque côté peut avoir des minima et maxima différents.

      hint

      Client vers commande, commande vers client.

      id

      technologies-conceptuel-logique-r2

    3. prompt

      Que contient le dictionnaire ?

      answer

      Sens, type, statut, domaine, validations/calculs et exemples.

      hint

      Pas seulement le nom.

      id

      technologies-conceptuel-logique-r3

    4. prompt

      Un champ facultatif est-il forcément multiple ?

      answer

      Non : optionalité et maximum sont des propriétés distinctes.

      hint

      Min et max.

      id

      technologies-conceptuel-logique-r4

    questions

    1. type

      mcq

      prompt

      Une commande doit appartenir à un seul client. Le lien côté Commande doit…

      options

      1. référencer un client valide et unique pour cette commande

      2. être un texte libre uniquement

      3. être supprimé

      4. autoriser plusieurs clients sans contrôle

      correctIndex

      0

      solution

      Le maximum est un ; le minimum est un pour une commande validée dans cette règle.

      id

      technologies-conceptuel-logique-q1

    2. type

      open

      prompt

      Définis un champ quantité de ligne.

      solution

      Entier positif ; obligatoire ; sens=nombre d’unités de cet article dans la commande ; domaine≥1 ou limites explicites ; exemple 2 ; calcul du montant selon quantité×prix vendu.

      rubric

      1. Sens métier.

      2. Type et domaine.

      3. Statut.

      4. Exemple/calcul.

      id

      technologies-conceptuel-logique-q2

    3. type

      open

      prompt

      Pourquoi le modèle ne doit-il pas être déduit seulement de l’écran actuel ?

      solution

      Un écran ne montre qu’une partie des besoins et peut masquer historique, relations ou utilisateurs. Partir des règles/processus et vérifier ensuite que l’écran les soutient.

      rubric

      1. Limite de la vue.

      2. Règles/processus en référence.

      3. Vérification de cohérence.

      id

      technologies-conceptuel-logique-q3
