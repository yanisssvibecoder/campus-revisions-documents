prerequisites

  1. technologies-si-strategie

analogy

Dans une école, le numéro d’étudiant identifie une personne même si son nom change. Une note appartient à cet étudiant en utilisant ce numéro, plutôt que recopier son adresse sur chaque note.

explanation

  1. Une table regroupe un type d’entité : Client, Commande ou Article. Une ligne est un enregistrement ; une colonne est un attribut. Une table ne doit pas mélanger arbitrairement des clients et commandes dans les mêmes lignes.

  2. La clé primaire identifie une ligne de manière unique et non vide. Une clé candidate pourrait remplir ce rôle ; on en choisit une. Un identifiant stable non significatif évite de casser les liens lors d’un changement de nom ou téléphone.

  3. Une clé étrangère (appelée clé lointaine dans le cours) référence une clé d’une autre table. Dans Commande, noClient indique quel Client est concerné. L’intégrité référentielle exige qu’un client référencé existe ; les règles précisent si le lien peut être vide.

  4. Un client peut avoir plusieurs commandes, mais chaque commande concerne un client dans notre règle. La clé du client est placée côté plusieurs, dans Commande. Le nombre de colonnes ne détermine pas la cardinalité.

  5. Une relation plusieurs-à-plusieurs exige une entité/table d’association. Commande et Article sont reliées par DetailCommande, qui porte quantité et éventuellement prix historique. Le prix du catalogue peut changer ; conserver le prix vendu évite de recalculer une vieille vente avec le nouveau tarif.

  6. Airtable distingue l’identifiant relationnel conçu, le champ principal affiché à l’humain et un identifiant technique interne. Le Name sert notamment aux listes Softr et peut ne pas être unique. Un libellé clair n’est pas un substitut à une clé stable.

  7. Le domaine d'un attribut est l'ensemble des valeurs permises. Son type précise leur nature (texte, entier, décimal, montant, date/heure, booléen); ses contraintes précisent obligatoire, unique, intervalle autorisé et référence à une autre table. Un téléphone est un identifiant de contact, pas une quantité à additionner : du texte ou un type téléphone évite de perdre ses zéros ou son format.

  8. NULLE signifie qu'une valeur n'est pas renseignée. Ce n'est ni zéro ni une chaîne comme «inconnu» saisie pour cacher l'absence. Rendre tous les champs obligatoires peut empêcher de créer un client dont on attend encore le téléphone. Les règles décident quelles absences sont permises; une clé primaire reste obligatoirement renseignée.

  9. Dans une clé composée (noCommande, noArticle), c'est le couple qui doit être unique. noCommande seul peut se répéter et noArticle seul aussi. Chacun des composants est renseigné. Si le même article peut apparaître deux fois dans la même commande avec des caractéristiques différentes, le couple ne suffit plus : la règle réelle exige un numéro de ligne ou une autre clé.

  10. Le schéma d'une table décrit ses champs; l'enregistrement est une occurrence réelle. CLIENT(noClient, nom) est un schéma; (101, Lina) est une ligne. Le DSBD représente tables, attributs, clés et liens. Dans le texte du cours, les clés primaires sont soulignées; les clés lointaines sont marquées selon sa notation. Le dictionnaire complète le dessin avec les contraintes de chaque attribut.

vocabulary

  1. term

    Entité

    meaning

    Type d’objet sur lequel on conserve des données.

  2. term

    Attribut

    meaning

    Propriété d’une entité.

  3. term

    Clé primaire

    meaning

    Identifiant unique et non vide d’un enregistrement.

  4. term

    Clé étrangère/lointaine

    meaning

    Référence d’une table à une clé d’une autre.

  5. term

    Intégrité référentielle

    meaning

    Cohérence des références entre tables.

  6. term

    Table d’association

    meaning

    Table qui matérialise une relation plusieurs-à-plusieurs.

  7. term

    Domaine

    meaning

    Ensemble des valeurs acceptées pour un champ.

  8. term

    Valeur nulle

    meaning

    Valeur non renseignée, à distinguer d'un zéro observé.

  9. term

    Clé composée

    meaning

    Plusieurs attributs dont le groupe identifie une ligne; chaque attribut peut se répéter séparément.

  10. term

    Schéma

    meaning

    Définition des champs et règles d'une table, avant ses lignes réelles.

  11. term

    DSBD

    meaning

    Diagramme de structure de base de données : tables, clés, attributs et liens.

formulas

    workedExamples

    1. title

      Client et commande — exemple original

      prompt

      Clients : 101 Lina, 102 Marc. Commandes : 501 client 101 ;502 client 101 ;503 client 999.

      steps

      1. 101 et 102 sont des clés client distinctes.

      2. Deux commandes peuvent référencer 101 : relation un-à-plusieurs.

      3. Client 999 n’existe pas : commande 503 viole la référence, sauf si une procédure la traite avant l’enregistrement validé.

      4. Créer le client légitime ou corriger le lien ; ne pas inventer un client pour masquer l’erreur.

      answer

      501/502 valides ;503 à corriger.

      pitfall

      Croire qu’une clé étrangère doit être unique dans la table enfant.

    2. title

      Le détail de la commande — exemple original

      prompt

      Commande 501 contient 2 pizzas article 10 et 3 boissons article 20. Une autre commande contient aussi l’article 10.

      steps

      1. Commande peut contenir plusieurs articles ; Article peut appartenir à plusieurs commandes.

      2. Créer deux lignes de DetailCommande pour 501 : (501,10,quantité 2), (501,20,quantité 3).

      3. Chaque ligne référence une commande et un article ; un identifiant de ligne peut être ajouté si le même article peut apparaître plusieurs fois.

      4. Le modèle de clé dépend des règles métier, pas d’une hypothèse universelle.

      answer

      Une table d’association rend quantités et liens explicites.

      pitfall

      Mettre «10,20» dans un seul champ sans lignes distinctes.

    3. title

      Une clé à deux morceaux — exemple original

      prompt

      Lignes de détails : (commande 501, article 10, quantité 2), (501,20,3), (502,10,1). La clé est commande+article.

      steps

      1. 501 se répète et article 10 se répète : chacun seul n'est pas unique.

      2. Les trois couples 501/10, 501/20, 502/10 sont différents : la clé composée est valide.

      3. Ajouter une autre ligne 501/10 sans autre identifiant violerait cette clé.

      4. Si la règle autorise plusieurs lignes pour le même article et la même commande, définir une clé de ligne adaptée.

      answer

      L'unicité concerne le couple, pas chaque colonne séparée.

      pitfall

      Marquer noCommande et noArticle individuellement uniques et empêcher une commande de contenir plusieurs articles.

    4. title

      Un petit dictionnaire — exemple original

      prompt

      Table COMMANDE : noCommande, noClient, dateLivraison, total. Une commande est créée avant livraison.

      steps

      1. noCommande : entier/identifiant, obligatoire et unique.

      2. noClient : référence obligatoire vers un client existant, répétition permise.

      3. dateLivraison : date facultative avant livraison; sa valeur nulle ne veut pas dire livrée le jour zéro.

      4. total : montant calculé selon la règle, distinct d'un identifiant ou d'une date.

      5. Le DSBD donne la structure; ce dictionnaire précise les valeurs admises.

      answer

      Chaque champ possède un sens et des contraintes cohérentes avec le processus.

      pitfall

      Rendre dateLivraison obligatoire dès la création et bloquer toutes les commandes non encore livrées.

    recall

    1. prompt

      Quelle propriété d’une clé primaire ?

      answer

      Unique et non vide ; idéalement stable.

      hint

      Identifier une seule ligne.

    2. prompt

      La clé étrangère doit-elle être unique ?

      answer

      Pas généralement : plusieurs commandes peuvent référencer le même client.

      hint

      Côté plusieurs.

      id

      technologies-tables-cles-r2

    3. prompt

      Où placer la clé étrangère en un-à-plusieurs ?

      answer

      Dans la table du côté plusieurs.

      hint

      Chaque commande a son client.

      id

      technologies-tables-cles-r3

    4. prompt

      Comment matérialiser plusieurs-à-plusieurs ?

      answer

      Avec une table d’association et des références vers les deux entités.

      hint

      Commande–Détail–Article.

      id

      technologies-tables-cles-r4

    5. prompt

      Pourquoi Name ne suffit-il pas ?

      answer

      C’est un libellé humain pouvant changer ou être dupliqué ; il faut des identifiants stables.

      hint

      Affichage versus identité.

      id

      technologies-tables-cles-r5

    6. prompt

      Dans une clé composée, chaque colonne doit-elle être unique ?

      answer

      Non. Le groupe doit être unique et chaque composant renseigné; un composant seul peut se répéter.

      hint

      Deux morceaux qui forment une adresse unique.

      id

      technologies-tables-cles-sc-r1

    7. prompt

      Qu'apporte un dictionnaire au DSBD ?

      answer

      Le sens, type et contraintes des attributs : obligatoire, unique, domaine et références.

      hint

      Le dessin seul ne dit pas toutes les règles de saisie.

    questions

    1. type

      mcq

      prompt

      Deux clients portent le même nom. La clé prénom+nom…

      options

      1. garantit l’intégrité

      2. est forcément unique

      3. peut être ambiguë

      4. doit devenir la clé étrangère de tous les articles

      correctIndex

      2

      solution

      Les noms ne garantissent pas l’unicité ; un identifiant stable est plus robuste.

      mcq

      prompt

      Un client et ses multiples commandes : noClient se trouve comme référence dans…

      options

      1. une seule ligne au hasard

      2. Commande

      3. Article uniquement

      4. aucune table

      correctIndex

      1

      solution

      Le côté plusieurs contient la référence au côté un.

    3. type

      open

      prompt

      Quel problème crée un prix de catalogue utilisé pour recalculer toutes les commandes historiques ?

      solution

      Un changement du catalogue modifie artificiellement les ventes passées. Stocker le prix convenu par ligne permet de préserver la transaction, tout en gardant le lien article.

      rubric

      1. Identifier réécriture du passé.

      2. Séparer prix actuel et prix vendu.

      3. Conserver un lien article cohérent.

      id

      technologies-tables-cles-q3

    4. type

      mcq

      prompt

      Dans une clé (noCommande, noArticle), quelle condition d'unicité est correcte ?

      options

      1. Chaque noCommande ne peut apparaître qu’une fois

      2. Chaque article ne peut apparaître qu’une fois

      3. Le couple ne doit pas être dupliqué

      4. Aucune valeur ne peut se répéter dans toute la table

      correctIndex

      2

      solution

      Une commande peut avoir plusieurs articles et un article plusieurs commandes. Leur couple identifie le détail selon la règle indiquée.

      id

      technologies-tables-cles-sc-q1

    5. type

      mcq

      prompt

      Un téléphone client est manquant. Peut-on le remplacer systématiquement par 0 ?

      options

      1. Oui, zéro signifie toujours inconnu

      2. Non, cela transforme une absence en donnée réelle et dépend des règles

      3. Oui, si le client commande deux produits

      4. Non, il faut supprimer le client dans tous les cas

      correctIndex

      1

      solution

      Une absence doit être représentée et traitée explicitement. Un champ peut être facultatif si le processus l'exige.

      id

      technologies-tables-cles-sc-q2

    6. type

      open

      prompt

      Rédige trois contraintes pour le champ noClient de COMMANDE, selon la règle : chaque commande appartient à un client existant, un client peut passer plusieurs commandes.

      solution

      Le champ est obligatoire; sa valeur référence un client existant (intégrité référentielle); il n'est pas unique dans COMMANDE, puisqu'un client peut passer plusieurs commandes.

      rubric

      1. Obligatoire.

      2. Référence à un client existant.

      3. Non unique côté commandes.

      4. Lien avec les règles du cas.

    masteryChecklist

    1. Je dessine Client→Commande et Commande→Détail←Article.

    2. Je reconnais une référence invalide.

    3. Je distingue clé, libellé et prix historique.

    4. Je distingue type, domaine, absence et contraintes.

    5. Je contrôle une clé composée sans imposer l'unicité de chaque composant.

    6. Je complète un DSBD par un dictionnaire compréhensible.
