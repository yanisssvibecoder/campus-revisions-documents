prerequisites

  1. technologies-processus-valeur

analogy

Un plan de métro indique des stations et des chemins ; BPMN indique des activités et des chemins de travail. Les couloirs montrent qui fait quoi, et les messages indiquent les échanges entre participants.

explanation

  1. BPMN utilise une notation pour représenter le déroulement d’un processus. Un événement de début lance le flux ; des tâches font le travail ; un événement de fin termine le chemin. Une tâche se nomme avec un verbe et un objet.

  2. Une piscine (pool) représente un participant ; un couloir (lane) répartit les responsabilités à l’intérieur de ce participant. La flèche de séquence relie les étapes à l’intérieur d’une piscine. Le flux de message représente un échange entre piscines, pas un ordre de tâches à l’intérieur d’un même participant.

  3. Une passerelle exclusive choisit un chemin selon une condition. Par exemple stock disponible oui/non. Les conditions doivent permettre de comprendre quel chemin s’exécute. Une passerelle n’est pas la tâche qui vérifie le stock : la vérification produit l’information utilisée.

  4. Un événement intermédiaire peut attendre un message ou un délai. Un objet de données représente une information manipulée et un magasin de données une conservation. Une association montre un lien à des données ; ce n’est pas le flux d’exécution.

  5. Un sous-processus fermé résume plusieurs étapes. Pour lire un modèle, trace un scénario concret du début à la fin et explique chaque tâche, responsabilité, condition et échange. Vérifie qu’aucune branche ne reste sans fin ou condition compréhensible.

  6. Repères visuels à dessiner de mémoire : début = cercle à contour simple; fin = cercle à contour épais; intermédiaire = cercle à double contour. L'enveloppe vide signale un message reçu, l'enveloppe remplie un message émis; l'horloge indique une minuterie. Le contour dit à quel moment du processus on se trouve, le pictogramme précise la nature de l'événement.

  7. Une tâche est un rectangle aux coins arrondis. Les marqueurs de l'aide-mémoire distinguent tâche manuelle (main), utilisateur (personne avec système) et service (engrenages, automatisée). Une piscine est un grand rectangle de participant, les couloirs ses bandes de responsabilités. Une passerelle est un losange; X indique une sélection exclusive. Le choix ne se confond pas avec l'activité qui calcule la condition.

  8. Flux de séquence = ligne pleine avec pointe pleine, à l'intérieur du participant. Flux de message = ligne en tirets, petit cercle à l'origine et pointe ouverte, entre participants. Association de données = pointillés; objet de données = feuille avec coin plié; magasin de données = cylindre. Une association ne fait pas démarrer la tâche suivante.

  9. Pour apprendre, reconstruis ces repères avec les descriptions et les exemples ici, puis trace le chemin d'un cas. Les figures d'un exercice officiel restent son énoncé à interpréter; elles ne créent pas une seconde lecture théorique du cours.

formulas

    workedExamples

    1. title

      Une commande simple — exemple original

      prompt

      Client envoie une commande au magasin. Magasin vérifie stock, expédie si disponible, informe le client sinon.

      steps

      1. Deux participants : Client et Magasin, donc deux piscines si tous deux représentés.

      2. Message Client→Magasin : commande.

      3. Dans Magasin : réception → vérifier stock → passerelle oui/non.

      4. Oui → expédier → fin ; non → informer indisponibilité → fin.

      5. Les messages vers Client relient les piscines ; les séquences restent dans Magasin.

      answer

      Deux scénarios traçables et responsabilités explicites.

      pitfall

      Dessiner une flèche de séquence à travers deux piscines.

    2. title

      Un paiement attendu — exemple original

      prompt

      Après envoyer facture, le magasin attend le paiement avant livraison. Pourquoi une attente de message est-elle utile ?

      steps

      1. Envoyer facture est une tâche.

      2. Le paiement est un événement externe attendu.

      3. Un événement de réception de message peut représenter cette attente.

      4. Une règle de délai peut prévoir relance ou annulation selon le cas.

      answer

      Séparer l’action d’envoyer de l’événement attendu, puis expliciter les règles.

      pitfall

      Dessiner « attendre paiement » comme une action qui force le client à payer immédiatement.

    3. title

      Dessiner deux participants — exemple original

      prompt

      Sur une feuille, représente un client qui envoie une commande; le magasin la reçoit, vérifie le stock puis accepte ou refuse. Deux cas fictifs : 4 unités en stock pour 3 demandées, puis 2 pour 3.

      steps

      1. Dessiner deux piscines : Client et Magasin. Entre elles, la commande est un flux de message en tirets.

      2. Dans Magasin, réception : cercle début avec enveloppe vide. Vérifier stock : rectangle arrondi.

      3. Losange X : condition stock ≥ demande. Pour 4≥3, chemin accepter; pour 2<3, chemin refuser.

      4. Chaque chemin atteint un cercle de fin épais. Les séquences pleines restent à l'intérieur de Magasin.

      5. La base de stock est un cylindre lié à la tâche par une association, pas par une séquence vers une autre piscine.

      answer

      Un message entre participants, une activité de vérification et un choix exclusif avec deux scénarios.

      pitfall

      Dessiner l'ordinateur ou le stock comme un participant extérieur uniquement parce qu'ils contiennent des données.

    recall

    1. prompt

      Séquence versus message ?

      answer

      Séquence : ordre des tâches dans une piscine ; message : échange entre piscines.

      hint

      Même participant ou deux participants ?

    2. prompt

      Passerelle versus tâche ?

      answer

      La tâche effectue la vérification ; la passerelle route selon son résultat.

      hint

      Travail versus choix du chemin.

      id

      technologies-bpmn-r2

    3. prompt

      Que représente une lane ?

      answer

      Une répartition des responsabilités au sein du participant.

      hint

      Qui fait la tâche ?

    6. prompt

      Trois contours d'événements BPMN ?

      answer

      Simple au début, double pour intermédiaire, épais à la fin; le pictogramme précise message ou minuterie.

      hint

      Commencer, attendre, terminer.

    7. prompt

      Comment distinguer séquence et message visuellement ?

      answer

      Séquence : ligne pleine, pointe pleine. Message : tirets, cercle initial, pointe ouverte; il relie des participants.

      hint

      Ordre interne versus échange.

      prompt

      Quelle flèche entre deux piscines ?

      options

      1. une clé étrangère

      2. flux de message

      3. flux de séquence

      4. aucune information possible

      correctIndex

      1

      solution

      Le flux de message décrit leur échange. La séquence ne traverse pas deux participants.

      prompt

      Décris deux branches d’un modèle avec paiement valide ou refusé.

      solution

      Début paiement reçu → contrôler résultat → exclusive ; valide : enregistrer paiement et confirmer → fin ; refusé : informer et demander autre moyen selon règle → fin.

      3. Deux chemins explicités.
